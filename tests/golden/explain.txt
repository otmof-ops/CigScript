======== E100 ========
E100 lexing error  (lex, lex family, since 1.0.0)

  kind of no: not one of the four  (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error)

  The source contains something the lexer cannot turn into tokens.

  what to type next: fix the character or literal the message names; `cig language` shows the forms

  known causes, ranked; doctor checks them in this order
  1. a character or literal the lexer does not know
     probe: source-line (the source line under the caret)
     remedy: fix it at the caret

  arises in: parse  ·  tags: beginner-likely

======== E101 ========
E101 unterminated string  (lex, lex family, since 1.0.0)

  kind of no: not one of the four  (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error)

  A string literal has no closing quote on its line.

  what to type next: close the string on the same line, or write \n for a newline inside it

  known causes, ranked; doctor checks them in this order
  1. the closing quote is missing, or sits on the next line
     probe: string-literal-scan (the line the string opened on, looking for where the quote should close)
     remedy: close the string on the line it opened; use \n for a line break inside it
  2. an escaped quote \" swallowed the closing quote
     probe: source-line (the source line under the caret)
     remedy: count the backslashes before the last quote; a raw 'single-quoted' string has no escapes

  arises in: parse  ·  tags: beginner-likely

======== E102 ========
E102 unknown escape  (lex, lex family, since 1.0.0)

  kind of no: not one of the four  (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error)

  A backslash sequence in a double-quoted string is not one CigScript knows.

  what to type next: use \n \t \r \0 \\ \" \$ \u{hex}; for a regex or a Windows path use a raw 'single-quoted' string

     remedy: write it as a raw 'single-quoted' string, which has no escapes at all
  2. a typo in an escape

     remedy: the escapes are \n \t \r \0 \\ \" \$ and \u{hex}

  arises in: parse  ·  tags: beginner-likely

======== E104 ========
E104 malformed number  (lex, lex family, since 1.0.0)

  kind of no: not one of the four  (a mistake in the text, in the arithmetic, or in CigScript; syntax, type or logic error; an internal error)

  A numeric literal does not fit in 64 bits or is not well formed.

  what to type next: use a float (add .0) for magnitudes beyond 9223372036854775807; -9223372036854775808 is valid with the minus directly in front

  known causes, ranked; doctor checks them in this order

  2. a stray character inside the number
     probe: source-line (the source line under the caret)
     remedy: digits and single underscores only: 1_000_000

  arises in: parse  ·  related: E503
